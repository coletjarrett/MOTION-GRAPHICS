Code-Driven Motion Graphics

A practical way to produce lower thirds, bumpers, timelines, scripture cards, maps and short animated films. Every frame is written in code, AI assistants do the building, and people keep every decision.

1. Summary

Each graphic in this library is a small program. The program answers one question: what does the picture look like at time t? Because every frame depends only on time and on the text supplied, frames can be rendered on any computer, in any order and in parallel, and they come out identical every time. An AI assistant writes and revises the programs from a short brief. A second AI model critiques the rendered frames. A person approves the look, the wording and the final cut.

Why this matters for a translation-heavy organisation: the text is data. A spreadsheet of names, dates or verse references becomes finished clips in every language, and scripts like Arabic mirror automatically. Changing one name means re-rendering one clip in seconds, with no project files to reopen.

No generated imagery. AI is used only to write drawing code. Every shape is plain geometry and every word is text we supply, so there is no synthetic photography, no likeness of real people, and nothing the model “imagined”. Each clip can be inspected line by line.

5. Where it fits and where it does not

Strong fits

  • Recurring graphics: lower thirds, location tags, scripture callouts, agendas, countdowns, program bumpers
  • Anything that multiplies by language: re-render the same design from a translated table
  • Explanatory graphics: timelines, maps with routes, simple diagrams and data
  • Consistency: a design system encoded once and applied the same way everywhere

Honest limitations

  • This is illustration and typography, not photorealism or character animation.
  • Production would use the organisation’s own fonts and design standards. The demo uses system fonts.
  • AI-written code still needs an experienced eye. The critique loop catches a lot, but not everything.
  • Synthesized voice and music suit scratch tracks and internal pieces. Published work would keep human narration and approved music.
  • Quality is set by review. The speed only helps if approval stays with people.

6. How it would slot into existing work

  • Editors receive ProRes 4444 files with transparency, which drop straight into Premiere, Resolve or Final Cut, as well as H.264 previews.
  • Templates live in a shared repository with version history, and a change to a template is reviewed like a document edit.
  • Translation teams supply text tables. Clips come back per language, with fonts chosen per script.
  • Rendering runs on a spare Mac or PC, or on several machines at once, since frames are independent.

7. Suggested next step: a four-week pilot

WeekGoal
1Choose three recurring graphics currently made by hand. Encode the team’s fonts, colours and spacing as a template “design system”.
2Build the three templates with AI assistance, and review with the design team.
3Render them in 5–10 languages from real translated tables, and hand them to editors.
4Compare hours and revisions against the current process, then decide whether to continue.
